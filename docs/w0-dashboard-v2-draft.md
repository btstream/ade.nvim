# W0 面板第二版设计草案（待审）

状态：**已确认（2026-11-18）**：第 5 节按“需要选择时弹窗”的规则；角色标签用 `label`；第 6 节一起做。依据：用户 2026-11-18 的测试截图与 5 条调整意见。

## 0. 截图里看到的问题（除 5 条意见外）

- 标题行重复出现了三次（成员 winbar、详情 winbar、详情正文），信息挤在一起。
- 看板只有纯文本：列之间没有分隔，卡片之间没有边界，`· -` 这类空字段占位很乱。
- leader 聊天里 ade-team 的工具调用显示成 `Other · execute` 加原始 JSON，看不出是在建卡、组队还是提问。
- leader 在 worker 还在**等待批准**时就给卡片指定了 `owner: w1`，被服务拒绝（`owner w1 is not a worker of the team`）。

## 1. 新布局：只留成员和看板

去掉收件箱和详情两个窗口。宽屏 tabpage 变成两栏（打开观察栏时三栏）：

```
 ade.nvim · team t3 · ~/tmp · active · workers 2/3 · turns 41/200 │ 流程 default · 阶段 core 1/2 │ ? 待回答 1  ⚑ 待批准 1
┌ 成员 ─────────────────────┐┌ 看板 ──────────────────────────────────────────────────────────┐┌ 观察 · leader ─────────┐
│ ...（第 3 节）              ││ ...（第 4 节）                                                   ││ （按 <CR> 时才出现）      │
└───────────────────────────┘└──────────────────────────────────────────────────────────────┘└────────────────────────┘
```

- **标题只有一行**，放在 tabline（整个屏幕宽），不再出现在任何窗口里。右侧是待处理数量：`? 待回答 N`、`⚑ 待批准 N`。按 `!` 重新弹出待处理的窗口（第 5 节）。
- **原来的收件箱内容去哪了**：需要你回应的项（提问、spawn 申请、权限、回合上限）都改成弹窗（第 5 节）；worker 发给你的普通消息用 `vim.notify` 提示，同时在发消息的成员行上显示 `✉ 1`，按 `<CR>` 时在观察栏里能看到。
- **原来的详情去哪了**：卡片上按 `<CR>` 打开一个浮窗显示全文（正文、字段、更新者、时间），`q` 关闭；不再常驻。
- 窄屏浮窗同样只保留成员和看板两段。

## 2. 成员栏宽度

- 新配置 `teams.dashboard.members_width`（默认 32 列）。窗口设 `winfixwidth`、`nowrap`，内容超出时按显示宽度截断，**不会**因为内容变长而变宽。
- 你在使用中可以用 `<C-w><` / `<C-w>>` / 鼠标拖动调整；调整后的宽度在这次面板打开期间保持（刷新、打开或关闭观察栏、`VimResized` 都不会把它弹回默认值）。关闭面板后下次打开恢复配置值。
- 看板占剩余宽度；观察栏打开时看板与观察栏平分剩余宽度（观察栏宽度同样可以手动调整并保持）。

## 3. 成员按角色区分

每个成员一块，左侧一条彩色竖条表示角色；leader 永远在最上面，和 worker 之间有一条分隔线：

```
▌★ leader            claude/opus     ● 工作中 0:42
▌   ↳ → w1 task C1
──────────────── workers 2/3 ────────────────
▌◆ w1  coder         opencode/ds-flash ● 3:10  C1
▌   ↳ 执行 cargo test -p service
▌◆ w2  coder         opencode/ds-flash ○ 空闲 12m
▌◇ r1  reviewer      pi/gpt6.1sol      ? 等你回答   ✉ 1
```

- **角色标签**：新增可选的 `label`（短名，最多 16 字符），由 leader 在 `team_spawn` 时给出，或写在流程成员里（`{name, template, label = "reviewer", ...}`）。没给时用模板名。
- **颜色**：leader 固定一种强调色；worker 按角色标签分配颜色（同一标签同一颜色，例如所有 coder 一种色、reviewer 另一种），颜色来自一组高亮组 `AdeTeamRole1..6`（默认链接到主题里的不同颜色，用户可以覆盖）。
- 每行显示 agent/模型的短名（`opencode/ds-flash`），完整模型名在观察栏标题里。
- **需要服务端补字段**：`team.list` 的参与者条目现在没有 `template`、`agent`、`model`，要加上（另加 `label`）。属于协议的小扩展（19.9 补充），不升 api 版本。

## 4. 看板：列和卡片在视觉上分开

```
┃ 待开发 2                ┃ 进行中 1                ┃ 审查中 0      ┃ 等你决定 1              ┃
┃╭──────────────────────╮┃╭──────────────────────╮┃              ┃╭──────────────────────╮┃
┃│ C1 断言库 assert.lua  │┃│ C3 hooks + pending    │┃              ┃│ C4 mock 测试替身       │┃
┃│ core · 未分配          │┃│ extra · ◆ w1 ● 3:10   │┃              ┃│ core · ◇ r1 ?         │┃
┃│ files=assert.lua      │┃│ tests=✓ 12            │┃              ┃│ 要不要保留旧 API？      │┃
┃╰──────────────────────╯┃╰──────────────────────╯┃              ┃╰──────────────────────╯┃
┃╭──────────────────────╮┃                        ┃              ┃                        ┃
┃│ C2 runner + reporter  │┃                        ┃              ┃                        ┃
┃│ core · 未分配          │┃                        ┃              ┃                        ┃
┃╰──────────────────────╯┃                        ┃              ┃                        ┃
```

- **列与列**：列之间用粗竖线 `┃` 分隔；每列的标题行用不同底色（`AdeBoardColumn1..6` 循环），标题写“列名 + 卡片数”；空列保持宽度，不会挤没。
- **卡片与卡片**：每张卡片是一个圆角框，卡片之间留一行空隙。框的边框颜色 = 负责人的角色颜色（未分配为灰色），所以一眼能看出哪张卡是谁在做。
- **卡片内容**固定三行：① id + 标题（加粗）；② 阶段 · 负责人（带角色符号和实时状态）；③ 最多一个字段或正文第一行（灰色）。空字段不再显示 `· -` 占位。
- **光标所在卡片**整框高亮（反色边框）；`<CR>` 打开详情浮窗，`m` 就这张卡片给 leader 发消息，`H` 看历史。
- 列多时仍然 `zh`/`zl` 横向滚动；列宽有下限（例如 24 列），放不下就滚动而不是压扁。
- 已归档卡片仍按阶段折叠在最下面一行。

## 5. 需要你做选择时弹窗（已定：规则与 Claude Code / opencode 一致）

**规则**：只有在需要你**从几个选项里选一个**时才弹窗；其他情况只提示，不打断。

| 事项 | 是否弹窗 | 说明 |
|---|---|---|
| 带选项的提问（`bus_ask_human` 给了 `options`） | 弹窗 | 选项 + “其他（自己输入）” |
| 不带选项的提问 | 不弹 | `vim.notify` 提示，成员行显示 `?`；在成员上按 `a` 或 `:Ade team answer` 打开输入框作答 |
| spawn 申请 | 弹窗 | 批准 / 拒绝（同组多个时加“全部批准”） |
| 权限请求 | 弹窗 | 沿用聊天里已有的权限选择界面 |
| 回合上限 | 弹窗 | 继续（重置计数）/ 保持暂停 |
| worker 发给你的普通消息 | 不弹 | `vim.notify` + 成员行 `✉ N` |


参照 Claude Code / opencode 提问时的交互：在编辑器中央弹出一个选择窗口。

```
╭─ r1（reviewer）提问 · team t3 ─────────────────────────── 1/2 ─╮
│ C4 的 mock 要不要保留旧的 API？保留会多两天工作量。               │
│                                                               │
│  ❯ 1. 保留旧 API                                               │
│    2. 删除旧 API，只保留新的                                    │
│    3. 其他（自己输入）…                                         │
│                                                               │
│  ↑↓/jk 选择 · 数字直接选 · <CR> 确认 · <Esc> 稍后再答             │
╰───────────────────────────────────────────────────────────────╯
```

- **带选项的提问**：显示提问者（带角色）、问题全文（markdown 渲染、自动换行）、`bus_ask_human` 给出的选项；最后总有一项“其他（自己输入）”，选中后变成输入框。确认后调用 `team.answer`。
- **spawn 申请**：显示模板、agent、模型、角色说明；选项“批准 / 拒绝”，同组多个申请时多一项“全部批准（N 个）”。
- **权限请求**：沿用聊天里已有的权限选择界面（`ui/permission_details.lua` 那一套），只是在 worker 的请求上也弹出，标题写明是哪个 worker。
- **回合上限**：“继续（重置计数）/ 保持暂停”。
- **什么时候弹**：在 Neovim 任何地方都会弹，不需要打开面板。为了不打断输入：处于插入模式、命令行或另一个弹窗里时，先只用 `vim.notify` 提示，等离开插入模式（`InsertLeave`）或空闲（`CursorHold`）时再弹。
- **多个待处理**：排队，一次一个，标题右侧显示 `1/2`；`<Esc>` 表示稍后再答，项目保持待处理，面板标题显示数量，按 `!`（面板里）或 `:Ade team answer` 重新弹出。
- 别的前端或别的窗口先回答了，弹窗自动关闭。

## 6. 顺带处理的两个问题

- **leader 聊天里的 ade-team 工具调用**按消息样式显示（和观察窗口一样）：`→ w1 task C1：…`、`看板：新建 C1–C4`、`组队：申请 w1、w2`、`提问：…`，不再显示原始 JSON。
- **给还在等批准的 worker 分配卡片**：允许 `owner` 是“待批准的 spawn 申请里的名字”；申请被拒绝时这些卡片的 `owner` 自动清空，并通知 leader。（另一种做法是只改提示词让 leader 批准后再分配；推荐前者，少一轮来回。）
