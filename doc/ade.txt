*ade.nvim* *ade.txt*  与 Agent 对话，界面参照 Zed 的 Agent Panel

==============================================================================
1. 简介                                                        *ade-intro*

ade.nvim 是一个 Neovim 原生的 Agent Client Protocol 客户端。
它不是把 Agent 的 TUI 嵌进终端窗口，而是用 buffer、split 和 extmark
自己渲染对话记录、工具调用和输入框。

默认连接 OpenCode：

    :Ade
    :Ade login     " 首次使用；执行 Agent 自己提供的登录方式

默认布局为原生左右分屏；edgy.nvim 是可选依赖，使用时显式配置 external。
需要 Neovim 0.13+（0.13 尚未正式发布时使用 nightly）。代码块语法高亮需对应语言的 Tree-sitter parser
与 highlights query；缺失时保留纯文本。界面文字为英文，默认使用 Nerd Font 图标。

2. 命令                                                      *ade-commands*

:Ade [子命令]                                               *:Ade*
    toggle       打开或隐藏面板（默认）
    open         打开面板，必要时启动 Agent
    hide         隐藏面板，不中断会话
    new          新建会话
    stop         中止当前回合
    sessions     打开会话浏览器（<CR> 切换，<C-d> 删除，输入即过滤）
    delete       同 sessions，在浏览器内用 <C-d> 删除
    model        切换模型
    mode         切换模式
    config       汇总切换全部会话选项（含布尔开关与思考级别）
    agent        切换 Agent；带名称时直接切换
    agents       打开 Agent 管理界面：安装 / 更新 / 卸载 / 切换
    install      安装托管 Agent：:Ade install <id> [version]（不带参数打开管理界面）
    update       更新托管 Agent：:Ade update <id> [version]
    uninstall    移除托管副本：:Ade uninstall <id>
    reconnect    重连并恢复当前会话
    login        按 Agent 提供的登录方式登录（终端或 authenticate）
    logout       退出登录；仅当 Agent 声明支持时可用
    disconnect   停止 Agent 进程
    permission   重新打开待确认的权限请求
    file         把当前文件附加到输入区
    files        从项目索引选择文件，插入 @引用，不打开文件或发送消息
    image        读取剪贴板图像并附加；带路径时附加该文件
    diagnostics  把当前 buffer 的诊断附加到输入区
    team         团队面板；:Ade team start [流程] / :Ade team close
                 （见 |ade-teams|）
    workflows    列出、查看、删除命名流程

:AdeLog                                                      *:AdeLog*
    打开日志文件。

:AdeCompletionRefresh                                *:AdeCompletionRefresh*
    清理项目文件索引缓存，下次补全或选择文件时重新扫描。

:AdeDebug                                                  *:AdeDebug*
    在命令行打印控制器状态。

工作指示器                                                  *ade-spinner*

输入区 spinner 使用 libuv timer，默认 ui.toolbar.animation_interval=120ms；UI 回调合并，
明确刷新 ade.nvim 的窗口 winbar，必要时回退 redrawstatus!。不切换窗口焦点。隐藏面板/切换到
其他标签页时停止，返回后恢复；已停止/关闭的 handle 在下一次状态、窗口、焦点同步时重建。

:AdeDebug 的 spinner 包含：
  state / timer_active            动画状态及 handle 是否存活
  ticks / frame_changes           主线程 tick 和帧变化计数
  last_tick_age_ms                距最近一次 tick 的时间
  max_tick_gap_ms                 历史最大 tick 间隔，不只包含解析耗时
  max_schedule_delay_ms           UV 回调到 scheduled UI 上下文的最大等待
  max_refresh_delay_ms            合并刷新任务在队列中的最大等待
  bar_evaluations                 winbar 表达式求值次数，不是物理屏幕绘制次数
  last_evaluated_frame            最近求值的运行中 spinner 帧
  redraw_backend                 targeted_winbar 或 redrawstatus!
  active_errors / last_error      当前错误阶段 / 最近历史错误

apply、redraw、tick、start 错误分别计数，每个连续错误阶段仅首次记日志，成功后允许再次报告。
API 版本不支持定向重绘时会记录 targeted_fallbacks / last_targeted_error 并使用兼容路径。
state=static 表示 ui.toolbar.animate=false，last_bar_status=waiting 表示等待权限，不是卡死。
动画按单调时间选择帧，不补放积压。主循环忙时仍会暂停；libuv 不提供后台线程上的 UI 绘制。
可结合 render.timings（ui.render.profile=true）和 transport 统计定位重型同步工作。

python3 tests/integration_spinner.py 是带 UI 的回归，需要额外测试依赖 pynvim。

3. 输入区                                                    *ade-composer*

进入 ade_input 窗口或缓冲区时自动切换到插入模式，离开时退出插入模式，避免把输入状态
带到转录区或编辑窗口。按 <Esc> 可暂时使用普通模式；离开后再次进入时恢复插入模式。

以下均为默认值，可用 keymaps.input 修改（见 |ade-keymaps|）。

<C-s>          发送；回合进行中且输入为空时改为中止
               keymaps.input.send
<C-c>          中止当前回合（普通模式）
               keymaps.input.cancel
q              隐藏面板（普通模式）
               keymaps.input.close_panel
<C-]>          附加当前选区（普通模式）
               keymaps.input.add_selection
<M-m> / M      切换模型（输入 / 普通模式）
               keymaps.input.pick_model
<M-b> / m      切换模式（输入 / 普通模式）
               keymaps.input.pick_mode
<S-Tab>        循环切换工作模式（输入 / 普通模式）
               keymaps.input.cycle_mode
<M-e> / gT     选择 Thinking Level（输入 / 普通模式）
               keymaps.input.pick_thinking
L              历史会话（普通模式）
               keymaps.input.pick_session
<M-a>          进入待回答的选择卡片（输入 / 普通模式）
               keymaps.input.focus_choice
<C-x><C-u>     补全 /命令 与 @文件（Vim 内置触发，不可配）
@path/to/file  发送时自动展开为附件

winbar 左侧显示模式徽标、模型名与可选用量；右侧显示状态图标/动画与队列数量。
Winbar 不显示供应商前缀；模型选择器优先使用 agent 上报的分组，其次按供应商前缀分组。
<S-Tab> 跳过 bypassPermissions 和 agent 标记为 full_access 的模式；仍可手动选择。
模式、模型和 Thinking Level
可以点击。自定义布局见 |ade-toolbar|。
普通选择器默认调用 vim.ui.select；过滤能力取决于用户接管它的 UI。

每个会话有独立的草稿和附件。面板隐藏后草稿仍保留。

4. 转录区                                                  *ade-transcript*

以下均为默认值，可用 keymaps.chat 修改（见 |ade-keymaps|）。

i / <C-s>      聚焦输入区
               keymaps.chat.focus_input
<CR>           打开光标所在位置的文件
               keymaps.chat.open_location
<Tab>          展开或折叠工具/思考块；不可折叠时聚焦输入区
               keymaps.chat.toggle_block
[b / ]b        上一个 / 下一个消息块
               keymaps.chat.prev_block / keymaps.chat.next_block
G / gg         最新 / 最早
               keymaps.chat.scroll_bottom / keymaps.chat.scroll_top
S              附加当前选区
               keymaps.chat.add_selection
F              附加当前文件
               keymaps.chat.add_file
R              附加诊断
               keymaps.chat.add_diagnostics
M / m          选择模型 / 模式
               keymaps.chat.pick_model / keymaps.chat.pick_mode
<S-Tab>        循环切换工作模式
               keymaps.chat.cycle_mode
gT             选择 Thinking Level
               keymaps.chat.pick_thinking
<C-n>          新建会话
               keymaps.chat.new_session
L              历史会话
               keymaps.chat.pick_session
<M-a>          进入待回答的选择卡片
               keymaps.chat.focus_choice
g?             帮助（内容按当前配置生成）
               keymaps.chat.help
q              隐藏面板
               keymaps.chat.close_panel

所有按键都是 buffer-local，不会污染全局映射。转录区只读，从输入区或其他窗口直接
切入时也会退出插入模式。默认 i / <C-s> 切到输入区，S / R 保留附加选区 / 诊断动作；
未绑定业务动作的插入入口（如 a、o、A、gi）静默忽略。关闭 focus_input 后 i 也静默
忽略。keymaps.chat 配置的业务映射优先于这些兜底映射。

工具调用卡片折叠时只显示标题和一行预览。展开后，execute（shell）调用会在输出
之前以 "$ 命令" 的形式显示完整命令行：优先取 agent 的 rawInput.command，没有
结构化输入时退回标题。标题栏仍会为适配面板宽度截断长命令，卡片内是完整文本。
多行命令逐行显示，命令与输出之间留一个空行。

文件修改的卡片标题区分 Edit 与 Write。ACP 没有 write kind，创建/覆盖文件也报成
edit，因此插件按工具输入判断：带旧内容（oldString / oldText / patchText）的是
Edit，只有新内容（content 等）的是 Write；输入未到达时退回标题里的 write/create。

edit / write / patch 的卡片展开后直接画出 diff：删除行用 DiffDelete 背景，新增
行用 DiffAdd，+/- 号单独配色，上下文行沿用卡片底色。只有一个 hunk 时不显示 @@
头，多个 hunk 才用它分隔。一次涉及多个文件时，文件之间画一条分隔线。超过
ui.diff.max_lines 或 ui.diff.max_bytes 时以一行
提示收尾，不会把整个文件倒进 buffer。

diff 行按被编辑文件自身的文件类型着色（.lua 用 Lua、.py 用 Python），颜色来自
treesitter 的 @capture 组，与普通 buffer 一致；红绿背景与语法前景同时生效。只解析
"要显示的几行"，成本与文件大小无关（30 行约 0.6ms，800 行约 13ms），并按内容缓存，
流式刷新几乎零成本。缺 parser、扩展名未知或超过 ui.diff.max_syntax_rows 时静默
退化为纯文本，diff 本身不受影响。ui.diff.syntax = false 可整体关闭。

这些卡片默认展开。agent 仍在执行时就会用 rawInput 里的变更出图，完成后替换为
权威的 diff。按 <Tab> 手动折叠后，后续更新不会再弹出；从历史加载或重连恢复的
卡片默认折叠，避免一次展开几十个 diff；回放提交后再产生的新 diff 恢复默认展开，
历史卡片保持折叠；同进程内切回缓存会话时保留原状态。
write 拿不到旧内容，按"全新增"展示并标注 (new content)。

5. 键位配置                                                *ade-keymaps*

    require("ade").setup({
      keymaps = {
        input = { send = "<C-CR>" },                        -- 单个键
        chat = {
          focus_input = { "i", "<C-s>" },                   -- 多个键
          toggle_block = "<C-t>",
          scroll_top = false,                               -- 关闭该绑定
        },
      },
    })

每个字段接受：单个键、键的列表、{ n = "...", i = "..." } 模式表，或 false。
只会绑定该动作实际声明的模式；转录区没有输入模式，因此那里写成
pick_model = { n = "T", i = "<M-t>" } 时 i 会被忽略。
两个动作在同一模式抢同一个键会在 setup() 时报错；<Tab> 与 <C-i>、<CR> 与 <C-m>
视为同一个键。按键必须写在所属视图下：直接写 keymaps.send 会报错，并提示
应写成 keymaps.input.send。

可配置的字段与默认值见 |ade-composer| 与 |ade-transcript| 两张表。
picker、会话浏览器等自绘浮窗内部的按键不在 keymaps 管辖范围内。

7. 与 edgy.nvim 集成                                          *ade-edgy*

    require("ade").setup({ layout = { backend = "external" } })

    -- edgy 配置
    opts = function(_, opts)
      require("ade.integrations.edgy").extend(opts)
    end

两个视图必须作为数组元素写进列表，不能写成具名字段。edgy 只遍历
ipairs(views)，具名字段会被完全忽略，导致输入框脱离 edgebar、布局错位：

    -- 正确
    right = {
      { ft = "ade_chat", title = "Agent", wo = { winbar = false } },
      { ft = "ade_input", title = "Message", size = { height = 8 },
        wo = { winbar = false } },
    }

    -- 错误
    right = {
      { ft = "ade_chat", title = "Agent" },
      input = { ft = "ade_input", title = "Message" },
    }

无法接管时 ade.nvim 会给出警告。

ade.nvim 创建两个普通视图：

    ade_chat    对话记录（只读）
    ade_input   输入区（可编辑）

由 edgy 决定它们的位置和尺寸。ade.nvim 不会持续调整窗口大小，也不会在窗口
被关闭后强行重开。

默认 ade.nvim 拥有两个 winbar。若想让 edgy 显示标题栏：

    require("ade.integrations.edgy").extend(opts, {
      title_winbar = true,
      toolbar_winbar = false,
    })

并将 ade.nvim 的 ui.title.placement 与 ui.toolbar.placement 设为 "off"。
views() 返回 { chat = ..., input = ... }，不能直接赋给 opts.right；使用 extend()
或手动将两项作为数组元素插入。左侧布局显式传 position = "left"，并同步 ade.nvim
的 layout.position。

8. 状态栏                                                  *ade-statusline*

ade.nvim 不修改 'statusline' 和 'laststatus'。交互信息全部放在输入窗口的
winbar 中，因此 laststatus=3（全局状态栏）下也能正常显示。

需要集成到自己的状态栏时：

    require("ade").statusline()   -- "◆" / "◆ ◌" / "◆ !"
    require("ade").status()       -- 结构化表

9. 窗口保护与选择器                                        *ade-protection*

ade.nvim 的两个窗口默认锁定到自己的 buffer（'winfixbuf'），:edit、:bnext 等操作
无法把对话记录或输入框替换成其它文件。关闭窗口与隐藏面板不受影响。

从面板 :split 会得到一个可用的普通窗口，而不是被锁死的副本。

需要关闭该行为：

    require("ade").setup({ layout = { lock_buffer = false } })

普通选择器（模型、模式、权限确认）默认通过 vim.ui.select 实现，
因此 telescope、fzf-lua、snacks.nvim 等插件会自动接管。需要改用内置浮动
选择器时：

    require("ade").setup({ ui = { picker = "internal" } })

会话浏览器独立使用 ui.session_picker，默认 snacks，不可用时回退到内置窗口。

==============================================================================
10. 工作目录                                                  *ade-cwd*

会话的工作目录默认与 Neovim 的 cwd 一致（vim.fn.getcwd()），可用 cwd 配置项
显式固定。:Ade sessions 的列表按该目录过滤；若为空，会自动退回展示 Agent 知道
的所有会话。

切换历史会话时使用该会话自己的目录发起 session/load，因为 ACP 规范要求 cwd 与
会话一致，不匹配时 Agent 会拒绝。目录末尾的 / 会被去掉（根目录除外），避免同一个
目录因写法不同被当成两个。

会话列表跟随 Agent 返回的 nextCursor 翻完所有页。

==============================================================================
11. 会话的加载与关闭                              *ade-session-lifecycle*

打开历史会话时按 Agent 能力选择方式：

  loadSession                      session/load，回放完整历史
  只有 sessionCapabilities.resume   session/resume，恢复 Agent 端上下文但不回放
                                   历史，并提示 history is not replayed
  两者都没有                        新建会话

切换会话、删除会话和退出 Neovim 时，若 Agent 声明 sessionCapabilities.close，
会发送 session/close 释放 Agent 端资源。退出时同步等待响应后再终止进程。

12. 安装 Agent                                          *ade-install*

不需要 npm install -g：ade.nvim 可以把 ACP adapter 装到 Neovim 数据目录。

    :Ade agents              管理界面（类似 :Mason）
    :Ade install claude      开始安装并打开管理界面显示进度
    :Ade install pi 0.4.0    安装指定精确版本
    :Ade update [claude]     更新一个；不带参数时更新全部有新版本的
    :Ade uninstall pi        移除托管副本

管理界面按状态分组（Running / Installed / Available / Not managed），
按键作用于光标所在的 Agent。安装在后台进行，可同时装多个，npm 输出实时
显示在该行下方；打开时在后台检查新版本（只运行 npm view）。

    i       安装（已安装时重新安装）
    u       更新；已是最新版时什么都不做
    U       更新全部有新版本的
    X       卸载托管副本
    C       检查新版本
    x       取消正在运行的任务（仅服务后端）
    <CR>    展开/收起详情
    s       把聊天切换到这个 Agent
    g?      帮助
    q       关闭

安装位置：stdpath("data")/ade/agents/<id>/releases/<版本>/。每个 Agent 只保留
一个版本，更新成功后旧版本被删除（正在使用的除外）。安装完成不会自动切换
Agent、开会话或登录。manager.ensure_installed = { "claude" } 可在启动后自动
安装缺失的 Agent；manager.confirm = true 时安装/卸载前会再弹确认框。

首版托管：
    claude   @agentclientprotocol/claude-agent-acp   Node.js 22+
    pi       @geohar/pi-acp（georgeharker/pi-acp）   需另装 pi CLI v0.80.4+
OpenCode 以独立 CLI 分发，仍自行安装；管理界面只报告它是否在 PATH 上。

注意：
  - 安装会运行 npm，第三方包可执行安装脚本，不是沙箱。
  - 更新失败或取消时旧版本保持可用；半成品目录会被清理。
  - 凭据、会话历史、Agent 自己的配置都不受安装或卸载影响。

服务后端（|ade-service|，且运行中的服务在 hello 里声明 install 特性）时，
安装/更新/卸载由 nvim_ade_server 执行（PROTOCOL.md 第 16 节）：npm 在服务
进程里运行，Neovim 退出后安装会继续；多个 Neovim 共用同一把 Agent 锁，
其他前端发起的任务会在管理界面里显示为进行中，可用 `x` 取消自己发起的任务。
直连后端（backend = "direct"）、Windows 或旧服务仍由 Neovim 自己运行 npm，
此时没有取消机制，按 `x` 会提示当前后端不支持取消。

启动来源： >lua
    require("ade").setup({
      agents = { claude = { source = "auto" } },
    })
<
    auto      有健康托管安装就用它，否则用预设命令（默认）
    managed   只用托管安装；缺失或损坏时明确报错，不回退
    external  只用配置的命令，不看托管安装

显式写了 command 或 args 的 Agent 始终按 external 处理，不会被托管安装覆盖；
只改 env 或 profile 不算覆盖。

13. MCP 服务器                                        *ade-mcp-servers*

通过 mcp_servers 把 MCP 服务器交给 Agent，同一份配置用于 session/new、

    require("ade").setup({

14. 面板尺寸                                                    *ade-sizing*

原生布局中 layout.width 为 0.05~1 时按编辑器宽度取比例，>1 时为绝对列数。
先应用 min_width / max_width，再限制为编辑器宽度的 60%；空间不足时可能小于
min_width。输入高度受 min_input_height / max_input_height 约束。external 模式
由布局管理器设置尺寸。两个窗口的局部 statuscolumn 均设为一个空格 " "。

构建面板时临时关闭 'equalalways'，两个窗口创建完并设置好尺寸后再恢复；否则
第二次 split 会立即重排，覆盖配置的宽度。

ade_chat 宽度变化时会自动重新排列表格、卡片和分隔线；拖动分屏、调整编辑器尺寸及
edgy 调整宽度均适用。连续调整采用 100ms 防抖，期间流式内容继续按上一次稳定宽度更新。
仅高度变化或其它窗口调整不会触发完整排版。阅读历史时尽量保留所在 block 的行偏移及
视口，不将重排标记为新消息；跟随输出时保持底部。隐藏后重开按实际窗口宽度重排。

鼠标需在当前模式启用：默认 'mouse' 为 "nvi"，已支持普通、可视和插入模式，
并不要求包含 a。设为空字符串会关闭鼠标支持。无法点击时也可用 <M-m>/<M-b>。

15. 会话标题与删除                                      *ade-session-titles*

标题显示在对话记录窗口的 winbar 中。为兼容未推送 session_info_update 的 Agent，
ade.nvim 在会话创建后、切换会话后及每回合结束后查询 session/list 来同步标题，
并按 session id 缓存；同时支持 Agent 推送的标题更新。
历史先重放到暂存对象，成功后提交；失败不覆盖旧历史与队列。同一时间只执行一次重放。
选择运行中的缓存会话时直接查看，不重新加载；旧加载结果不会覆盖较新的选择意图。

:Ade sessions 默认使用 snacks.nvim 的 picker：自带 fuzzy 搜索、实时预览，并沿用
用户已有的 snacks 主题。未安装 snacks 时自动回退到内置窗口。

    <CR>        切换会话
    <C-d>       删除会话（二次确认）
    输入        fuzzy 过滤
    <Esc>/q     关闭

列表右侧显示更新时间，当前会话行首有箭头标记，右侧预览显示完整会话 ID、目录与
时间。删除后列表原地刷新，可连续删除。

强制使用内置窗口：

    require("ade").setup({ ui = { session_picker = "internal" } })

内置窗口（回退时）支持 j/k 移动与 <BS>/<C-u> 编辑过滤。
q 关闭，gg/G 跳到首项/末项；需要搜索保留字母 j/k/q 时用大写 J/K/Q。

删除非当前会话不影响当前对话；删除当前会话会自动新建一个。Agent 未声明
sessionCapabilities.delete 时给出提示，不弹出无法兑现的确认框。

16. 行为细节                                                *ade-behavior*

同一会话同时只运行一个 prompt；生成中提交的消息本地排队。
默认最多排队 16 条、估算载荷 4 MiB，超过时拒绝入队并保留输入。
队列属于会话运行时，切换窗口不暂停后台队列；历史替换共享 outbox，不丢失待发送消息。
队列仅保存在当前 Neovim 进程，退出或崩溃后不恢复。

重新 setup() 会取消旧环境任务；待发送队列非空时默认拒绝重新配置。确实需要丢弃时：

    require("ade").setup({}, { discard_queued = true })

Agent 崩溃后使用 :Ade reconnect。重连会通过 session/load 重放 Agent 侧
历史，但不会自动重发上一条 prompt。
断连暂停队列；恢复当前会话后继续尚未开始的消息，其他会话在选中并恢复后继续。
已发请求不自动重试，避免重复工具操作；这不是远端执行 exactly-once 保证。

未发送的草稿保存在 stdpath("state")/ade/drafts.json，重启后自动恢复。
磁盘草稿最多 50 条，内存历史草稿默认最多 20 条。磁盘保存合并 150ms 后异步写入，
退出时 flush；崩溃可能丢失尚未持久化的最近修改。
草稿保存显式绑定项目与会话，切换或重入不会误写另一个会话；仅附件的草稿也会保留。

控制器使用 block 版本和变更日志，仅重建变化块及受影响的后缀。窗口宽度变化、主题
切换或变更日志落后时使用完整渲染。代码语法缓存跨宽度复用，最多 64 项/约 2 MiB；
超过 256 KiB 的单个代码块显示纯文本，单块最多保留 20,000 个语法捕获。

memory.* 限制本地保留载荷，不是 Lua/Neovim RSS 硬上限。超大 block 显示截断标记，
会话超预算会移除最旧记录，不修改 Agent 侧历史；重新加载仍应用同样预算。
闲置会话按 LRU 淘汰，当前、运行中、有队列或权限请求的会话受保护，可暂时超过
缓存数量/总载荷预算。渲染缓存和 Neovim 对象仍有额外开销。

可选懒渲染                                                   *ade-lazy-render*

默认 ui.render.lazy_syntax=false，ui.render.pagination.enabled=false，保留原有全文路径。
建议先开启 lazy_syntax（A），再按需开启 pagination.enabled（B）：
>
    ui = { render = {
      lazy_syntax = true,
      profile = false,
      budget_ms = 4,
      overscan = 1,
      commit_rows = 2000,
      pagination = {
        enabled = false,
        page_blocks = 64,
        max_blocks = 192,
        page_bytes = 256 * 1024,
      },
    } }
<
A 保留全文文本、conceal、基础高亮和背景，只按视口延迟代码及 diff 的语法装饰；
原生搜索、复制、位置跳转不变。语法缓存有独立预算，远处的语法 extmark 会清理。
B 按连续 block 范围物化历史，分页排版逐 block 让出主循环。最新消息始终自动追加；只有更早
的历史按需加载，接近顶部时预取相邻页，顶部保留“更早消息”提示，可按键加载。
gg 加载最早保留内容，G 回到最新并跟随，[b/]b 可跨页。

接收尾部、分页排版、语法装饰与大型提交使用共享调度器；接收首次回调与消息派发仍有独立预算。
stdout 未处理尾部保序排队并计入积压限制，溢出时明确断连；分页中的表格、Markdown 在结构行边界让出；
超过 commit_rows 的首次布局或翻页提交按行分片，期间可继续响应输入与刷新 spinner。
分片依赖协作式让出，单个 JSON 解码、一次 Treesitter 解析、diff 计算、非分页排版和单条消息分帧仍不可抢占。

分页开启后，原生 /、Visual 复制只覆盖已加载文本；不提供全历史原生搜索。Session 与
Agent 历史不变，Chat:transcript() 显式全文导出仍完整，但会临时执行全量文本排版。
最新消息不受分页限制，始终物化并自动追加；往回加载只会扩展旧侧窗口，不会隐藏新内容。
返回底部时旧侧窗口收回预算，可见内容与操作中的卡片受保护，因此预算不是硬上限。
Visual/Select 选区活动时暂停分页物化修改，退出后自动补齐最新内容。
单个 block 不做块内分页，继续受原有 memory.* 限制。
page_bytes 是旧侧每页的源载荷目标；回收同时参考 max_blocks 和页面数量推导的字节预算，
不是 RSS 上限。完整 JSON 解码、单块排版及单次 Treesitter 解析仍不可抢占。

profile=true 时 :AdeDebug 的 render 展示分层 timings、物化行数、缓存块数、语法 extmark
数量及分页范围。每个阶段除 count/total/max 外还有按 1/2/4/…/1024ms 的延迟桶与溢出计数；
slow_tasks 保留最近 20 条超过 8ms 的任务（名称、耗时、block id/kind/工具类型/载荷规模，
不含正文）。first_paint 是首个布局提交耗时，不是物理屏幕绘制耗时；layout_slice 是分页
排版时间片，block_layout 是单块排版，syntax 是实际装饰解析调用耗时，write 含分片提交。
transport 统计另有输入重入计数，可与 spinner 的 max_tick_gap_ms 交叉定位。

transport.max_pending_bytes 默认 64 MiB，限制尚未消费接收数据（不完整消息、待分发
消息、尚未完成的文本分片、在途写入与已读缓冲）的估算开销；设为 0 关闭积压上限。
spill_bytes 默认 64 MiB，是完整 JSON 行异步落盘的工作集目标；设为 0 则只占内存。
两者为正时，落盘阈值最多为上限的 75%。磁盘旧消息优先于内存新消息，当前文本分片
又优先于所有后续消息。回调时间预算到期后，未处理的输入尾部进入共享调度队列，
下一片继续解析，保持顺序且不丢弃；输出批次超出预算时同样让出。
阈值不是 RSS 硬上限：输入回调、JSON 对象和临时复制仍有额外开销；磁盘慢于输入时，
有限预算仍可能触发断连。单条 JSON 解码、工具替换更新或单块排版仍不可抢占。

超过 transport.text_chunk_bytes 的文本型 session/update 会在完整解码后按 UTF-8 边界
切片，通过惰性派发器直接归约已解码片段，不重新编码或进入分片检测；片间可让出主循环。
仅处理 agent/user/thought 追加文本。工具内容、diff 和 rawOutput 保持原子替换，避免
累计前缀的二次方复制；其它消息仍整条处理。完整 JSON 解码的峰值内存仍然存在。

落盘文件位于 `stdpath("run")/ade.nvim/ade-spill-*`，权限 0600，排空、停止或退出时删除；
停止时若尚有 I/O，等待其回调后释放文件描述符。创建/写入失败回退内存；读取失败明确
报错并断连，不在缺失消息后继续运行。超过 24 小时的崩溃残留会在下次启用落盘时清理。
文件是原始协议正文，未加密。

`max_pending_bytes = 0` 且 `spill_bytes = 0` 时永不因总积压断开，代价是可能耗尽内存，
只适合确定历史规模的环境。回放期间超限日志会带 `phase=replay`；摘要包含积压、上限、
触发行大小、本次回调消息数、累计消息/字节、最大输入、落盘记录与批次耗时，不含正文。
16/64/256/1024 MiB 会各告警一次。开启 `log.protocol` 还会逐回调记录明细。
通知归约在该预算内执行；权限 UI 单独调度，旧连接的模型/权限选择器不会影响新状态。

思考块在流式期间实时展开并显示 Thinking，结束后自动折叠并显示 Thought；历史与重连
重放保持折叠。跟随时超过一屏的内容保持尾部锚定，保留原有尾部空行，后续内容继续追加。
不足一屏时从顶部显示，不添加顶部留白；鼠标不能继续下滚来扩大自然剩余空白。聊天窗口启用
局部 smoothscroll，处理高于一屏的换行文本；不改变其它窗口的滚动设置。
鼠标上滚离开末尾暂停自动跟随，下滚回到实际末尾恢复跟随并清除新消息提示，不依赖光标位置。
暂停跟随不暂停消息接收或 buffer 追加；自动折叠、重排和其它窗口的滚动不会触发恢复跟随。
手动 <Tab> 优先。ui.thoughts.expand_while_streaming / collapse_on_finish
可关闭对应行为。

权限选择器按 Esc 或 q 关闭视为拒绝；若 Agent 没有提供 reject 选项，则返回
cancelled。

17. 轮次分隔符                                          *ade-separator*

每两轮对话之间画一条细分隔线。默认中间一个圆点：

    ────────────────────────── ● ──────────────────────────

ui.separator.form 控制样式：

    "dot"    细分隔线 + 居中圆点（默认）
    "turn"   细分隔线 + 轮次，形如 `Turn 2`
    "off"    不画分隔符

    require("ade").setup({

面板太窄、放不下两侧的线时，只保留中间的标记。分隔符不绑定任何 block，光标停在
上面时 <Tab> 不会误展开相邻的卡片。

18. 高亮                                                    *ade-highlights*

样式为静态定义，多数组链接到 Neovim / Tree-sitter 组；模式徽标默认使用固定颜色，
可通过 ui.highlights 覆盖。插件不会在运行时混合主题颜色。
正文里的 Markdown（粗体、斜体、删除线、标题、引用、链接）链接
到 treesitter 的 @markup.* 捕获组，所以在对话记录里的呈现和普通 Markdown buffer
遵循相应主题样式，但并非完整的 Markdown 实现。

两处例外，都是为了让表格读起来安静一些：

- 行内代码链接到 String。@markup.raw 在多数主题里是暖色强调色，放在正文中
  会抢注意力。
- 表格边框链接到 NonText。@punctuation.special 会被主题染成橙色、品红之类
  的高亮色，整个表格会变成霓虹网格。

常用的组：

    AdeUser  AdeAssistant  AdeToolTitle  AdeToolRunning
    AdeToolSuccess  AdeToolError  AdePlan  AdeSeparator
    AdeTitle  AdeToolbar  AdePermission  AdeStreaming
    AdeUserIcon  AdeUserTitle  AdeAssistantIcon  AdeAssistantTitle

工具卡片里的 diff 使用主题自带的 diff 组，红绿配色与 review 窗口一致；行内文字
另按所在文件的 treesitter @capture 着色，两层叠加而不是互相覆盖：

    AdeDiffAdd  AdeDiffDelete  AdeDiffAddSign  AdeDiffRemoveSign
    AdeDiffHunk  AdeDiffMeta  AdeDiffFile

AdeDiffAdd / AdeDiffDelete 是整行背景（链接 DiffAdd / DiffDelete），+/- 号单独
成组，便于主题只给背景色时单独调整；AdeDiffMeta 同时用于卡片内的分隔线与
"已省略 N 行"提示。

插件自绘的 picker（ui.picker = "internal" 的选择框、:Ade sessions 的内置窗口）
使用另一套 AdePicker* 组，默认链接到主题组：

    AdePickerNormal  AdePickerBorder  AdePickerTitle
    AdePickerSelection  AdePickerItem  AdePickerMatch
    AdePickerCurrent  AdePickerCurrentItem  AdePickerDescription
    AdePickerMeta  AdePickerEmpty  AdePickerSeparator
    AdePickerPrompt  AdePickerFooter

AdePickerNormal / AdePickerBorder / AdePickerTitle 通过 winhighlight 映射到浮窗
的背景、边框和标题，所以能在 style = "minimal" 的浮窗里单独改色，不必修改全局的
NormalFloat。AdePickerItem 链接到 Normal：浮窗里 Normal 已被 winhighlight 映射到
AdePickerNormal，snacks 列表里它则保持列表自身的背景色。snacks 后端的会话浏览器只用行内的组
（AdePickerItem / AdePickerCurrent / AdePickerCurrentItem /
AdePickerDescription / AdePickerMeta），窗口外观沿用用户自己的 snacks 主题。

ade_chat 的标题栏（winbar）与正文共用同一个背景（AdeNormal），读起来是对话记录
的页眉，而不是一条独立的色带。ade_input 的工具栏仍然用 StatusLine 的颜色，因为
它是工具栏而非页眉。

对话记录的标题行拆成图标和文字两组。默认 AdeUserTitle 链接到
AdeUserIcon；助手的两组均链接到 Keyword。想区分时
单独覆盖即可。助手回合开头的 Markdown 标题会用 AdeAssistantTitle，正文中间
的标题仍保留各自的 AdeH1-AdeH4 级别。

两种覆盖方式，都会优先于内置定义。通过 setup 传入：

    require("ade").setup({
      ui = {
        highlights = {
          AdeUser = { link = "Function" },
          AdeToolTitle = { fg = "#7aa2f7" },
        },
      },
    })

或者随时直接设置：

    vim.api.nvim_set_hl(0, "AdeUser", { link = "Function" })

切换 colorscheme 后会重新应用内置定义和 ui.highlights 配置；直接 nvim_set_hl 的
临时覆盖不保证保留，需要持久化时使用配置或自己的 ColorScheme 回调。
工具栏在 Neovim 0.12+ 使用继承背景的高亮语法；0.10/0.11 使用兼容语法，外部布局
插件重映射 WinBar 时颜色可能有所不同。

提问卡片默认随主题配色。可在 ui.highlights 中覆盖 AdeChoiceTabActive（当前标签）、
AdeChoiceOptionActive（焦点选项文字）、AdeChoiceFocus（焦点行背景）、
AdeChoiceSelected（已选标记）、AdeChoiceMuted（说明）和 AdeChoiceHint（快捷键）。

ui.icons = false 为主要图标选择 ASCII 默认集；ui.icon_overrides 可逐项覆盖。

输入区 Winbar                                                *ade-toolbar*

ui.toolbar.sections.left / right 配置组件顺序；空列表清空该分区。不配置时
沿用原布局。内置组件为 mode、model、thinking、attachments、context、
cost、status、queue。比如： >lua
    require("ade").setup({
      ui = {
        toolbar = {
          component_separator = { text = " · ", hl = "Comment" },
          sections = {
            left = { "mode", { "model", separator = { text = " │ ", hl = "NonText" } }, "thinking" },
            right = { "status", "queue" },
          },
        },
        icon_overrides = {
          status_idle = "○",
          modes = { claude = { acceptEdits = "E", plan = "P" } },
        },
      },
    })
<
组件支持 color、padding、cond(ctx)、fmt(text, ctx) 和 priority。也可直接使用
function(ctx) 返回文字。分隔符可写成字符串、{ text, hl }、false，或用
{ left = ..., right = ... } 为组件两边分别配置。未指定 hl 时继承所属组件的高亮；
全局分隔符默认继承前一个可见组件的高亮。显式 hl 优先，不影响组件文字。

模式图标按 agent 名、profile 名和 ACP mode ID 匹配。其他图标及 spinner_frames
同样通过 ui.icon_overrides 设置；设为 false 可关闭单项。
Claude 的已知模式自带图标和独立的 Winbar 高亮组。可通过
ui.toolbar.mode_highlights.claude.acceptEdits = "MyEditBadge" 逐模式指定高亮组；
先匹配 agent 配置名，再匹配 profile，mode ID 区分大小写。
require("ade").pick_thinking() 可用于自定义键位，只列出当前 agent 提供的档位。

20. 输入区补全                                               *ade-completion*

默认用 <C-x><C-u> 补全 /命令 和 @文件；索引异步建立，完成后显示原生菜单。
可选 blink.cmp / nvim-cmp 原生 source（选择一个），只在 ade_input 中生效。
两者共用解析器、文件索引与替换范围，保留当前会话命令说明，不执行命令或自动发送。

blink.cmp：将 sources 合并进已有 setup/opts： >lua
    sources = {
      per_filetype = { ade_input = { "ade" } },
      providers = {
        ade = { name = "ade", module = "ade.completion.blink" },
      },
    }
<
nvim-cmp：在两个插件可 require 后注册并设置 filetype 配置： >lua
    local cmp = require("cmp")
    require("ade.completion.cmp").setup()
    cmp.setup.filetype("ade_input", {
      enabled = true,
      sources = { { name = "ade", keyword_length = 0 } },
      matching = { disallow_symbol_nonprefix_matching = false },
    })
<
不修改全局 sources 和映射；若自己的 enabled 排除了 nofile buffer，需要放行 ade_input。
建议 <C-s> 发送，框架按键确认补全；如用 <CR> 发送，必须自行处理菜单选中项优先确认。
完整 lazy.nvim 示例见 examples/completion_blink.lua 与 examples/completion_cmp.lua。

@ 引用支持无扩展名、中文、空格和引号。带特殊字符时使用 JSON 字符串语法：
    @Makefile  @lua/ade/init.lua  @"docs/中文 file.txt"
邮箱中的 @ 不匹配。补全与发送使用相同语法；发送时才附加可读文件，不预读所有文件正文。

completion 默认值： >lua
    completion = {
      native = true, max_items = 200, picker = "vim",
      files = {
        backend = "auto", command = false, root = false,
        hidden = true, ignored = false, cache_ms = 10000,
        max_bytes = 16 * 1024 * 1024, max_projects = 4,
      },
    }
<
auto 依次选 rg --files、fd/fdfind、git ls-files，最终回退异步目录遍历。内置遍历不解析
ignore 文件，建议安装 rg/fd。root=false 从会话 cwd 找 Git 根目录，否则用会话 cwd；
也可设绝对路径或 function(cwd) return root end。插入路径始终相对会话目录。
hidden/ignored 遵循所选工具规则，.git 固定排除。ignored=true 可能显示敏感的被忽略文件。
command 可设 argv，cwd=root，要求输出 NUL 分隔路径；不会拼 shell 字符串或把查询当命令。
max_bytes 估算索引路径和条目开销，不是总 RSS 限制；超限明确报错，不悄悄截断。
max_items 只限制原生菜单，先匹配完整索引再截取；框架与文件选择器获得完整索引。

:Ade files / require("ade").pick_file() 使用 completion.picker 选择完整项目索引中的文件，需先打开输入区。
picker 可选 vim（vim.ui.select）、fzf-lua、snacks、telescope，不设强依赖；缺少所选工具时报错。
也可 require("ade").pick_file({ backend = "fzf-lua" }) 单次选择。可选映射：
    keymaps = { input = { pick_file = "<M-f>" } }
默认不占用按键；选择后插入引用并回到输入区，与 :Ade file 附加当前文件不同。
取消、会话切换、buffer 销毁或查询过期后，旧结果不会修改输入。

21. 图像附件                                             *ade-images*

输入区可附加图像，以 ACP image 内容块发送，要求 Agent 声明
promptCapabilities.image（OpenCode 支持）。未声明的 Agent 不会让消息失败：
图像在发送时降级为 resource_link（附带磁盘 URI），其余文字照常送达。
resource_link 形式本来就不受此限制。

用法：
    :Ade image              读取系统剪贴板中的截图并附加
    :Ade image path/to.png  附加指定文件
    直接粘贴 / 拖拽图像文件路径（只对输入区生效）

Lua API：require("ade").paste_image()、require("ade").add_image(path)。

配置： >lua
    context = {
      images = {
        enabled = true,
        max_bytes = 3 * 1024 * 1024,
        max_per_message = 4,
        clipboard = "auto",  -- 或 false，或自定义 argv
        path_mode = "link",  -- "link" | "inline"
        ttl_hours = 24,
        max_cache_bytes = 64 * 1024 * 1024,
      },
    }
<
clipboard = "auto" 依次尝试 wl-paste、xclip、pngpaste、powershell.exe。
也可给 argv（stdout 即图像字节），以复用已有截图工具。

paste_image 默认绑定 <C-v>（普通与插入模式），与 OpenCode TUI、pi 的习惯一致。
这会覆盖输入区的 i_CTRL-V（字面量插入）和普通模式 CTRL-V（块选择），
仅在 ade_input 内生效。需要换键时：
    keymaps = { input = { paste_image = "<M-v>" } }

图像在 ade_input 粘贴光标处插入 [Image 1] 可编辑占位符，多张图片独立编号，不放在 winbar。
默认浅黄色底、深色粗体，可通过 ui.highlights.AdeInputImage 覆盖。
这不是像素预览；光标放在占位符之后，可正常移动到两侧。在后方按退格或前方按 Delete
整块删除附件，支持撤销/重做。发送时移除受跟踪的占位符，不影响用户手写的同名文字。
ACP 内容块按输入区的文字/图片顺序交错发送；聊天记录也在原位置显示图片编号，
不把图片挪到标题或末尾。排队消息保存独立的位置快照，不受后续输入编辑影响。
异步读取的位置跟随文本编辑；清空或切换草稿后丢弃旧结果，不抢焦点、不强制恢复插入模式。

为什么不使用终端的粘贴快捷键：终端只在 bracketed paste 中传文本，截图不会
到达 Neovim；OSC 5522 需要终端专用协商并改变普通粘贴处理，本插件暂不接入。
目前由插件主动读取剪贴板，与 OpenCode TUI、pi 等终端客户端一致。

图像只在发送时编码。草稿、本地队列和会话块只保存路径、大小与 sha256，避免
base64 在三处各放大 33%。字节存放在 stdpath("state")/ade/images（目录 0700、
文件 0600），按 ttl_hours 与 max_cache_bytes 回收。max_bytes 会与
transport.max_line_bytes 交叉校验，配置阶段即拒绝装不进一条消息的上限。
path_mode = "inline" 时 @shot.png 会内嵌字节；默认 link 只发引用。
缓存清理保护当前草稿、持久化草稿、内存队列与会话块仍引用的图片，因此这些引用
可能使缓存超过配置预算。文件被外部删除后，发送会明确报错，而不是静默丢掉图像。

22. 选区与未保存的 buffer                       *ade-context-blocks*

@文件、S（附加选区）和 R（附加诊断）的内容能否内嵌，取决于 Agent 是否声明
promptCapabilities.embeddedContext：

    Agent 声明     未保存 buffer / 选区 ->  resource（内嵌文本）
    Agent 未声明   同上                ->  resource_link + 一段 text 块

未声明时仍然把文本发过去，而不是只发一个 file://...#L10:20 链接：否则 Agent
得自己去读文件，而你未保存的修改它根本看不到。这个判断发生在发送时，不是附加时
——附件可能长期留在草稿里，期间可能重连或切换 Agent。

23. 内联编辑                                            *ade-inline*

require("ade").inline() 在光标处或 Visual 选区打开输入框，由 Agent 修改当前
buffer。默认绑定 <leader>ai（普通和 Visual 模式）。Visual 选区按整行处理；
无选区（普通模式）时按用户请求修改副本，不限制为“光标处插入”；
inline.scope = "context" 时才把可编辑范围限制在光标周围的上下文窗口。

要求 Agent 编辑同目录的私有副本（.ade-inline-*，0600）；编辑权限仅授权本次副本，
其它文件的写入或命令默认拒绝。读取、搜索、思考、取回默认放行。这不是操作系统
沙箱，无法阻止绕过 ACP 权限协议的直接写入。目录不可写时退回 stdpath("state")。
结果按选区过滤；expand_selection=false 保留精确字符范围，块选区始终保留列范围。
等待或审查期间源内容、文件名或换行约定变化会拒绝应用。回合进行期间源 buffer 被锁定：
不能编辑，:w/:update 和自动保存也不会写盘并给出提示；取消或回合结束才解锁，应用结果和
审查前必定先解锁。副本在请求结算后删除，正常退出清理；下次使用时尝试清理超过一天且
所属进程已退出的孤儿。inline.max_copy_bytes 默认 8 MiB，限制副本/结果大小。

审查方式：

    inline.review.mode = "diff" | "write"

diff 默认在新 tabpage 中打开并排的真实窗口：3-column 为「原文 │ 结果 │ 提案」，
2-column 为「结果 │ 提案」。各栏不使用 Vim 的 diff 模式（它会让所有 diff 窗口互相比较，
无法表达「原文↔结果」「结果↔提案」两组对比）：插件按同一份对齐表给每栏插入 filler 行，
三栏行数相同，scrollbind/cursorbind 由 Neovim 原生同步。审查不修改 diffopt。
默认不折叠任何行：分栏窗口显式设成不折叠（foldmethod=manual、foldlevel=99），既不折叠
无关上下文，也不继承用户全局的 foldmethod/foldlevel；fold = true 才折叠离变更超过
context 行的未修改行。
结果列初始等于原文、是 nomodifiable，只展示决定结果。宽度不足 min_split_width 或
target = "float" 时回退为工具卡片渲染（同样的 diff 背景与语法高亮）。

对齐：块内的行用 linematch 按相似度配对；块里没有相似行（整段改写、翻译）时从上到下
配对。有对应的行为 modify（两侧都有内容），只在原文中的为 delete、只在提案中的为 add
（对面一定是 ╱ filler）。着色与对齐来自同一份数据。

每栏只显示自己这一侧相对结果的变化：
  原文  pending: AdeReviewDelete + AdeReviewDeleteText   接受: AdeReviewDimmed   拒绝: 无底色
  结果  pending: AdeReviewPending   接受: AdeReviewAdd + AdeReviewAddText   拒绝: 无底色
  提案  pending: AdeReviewAdd + AdeReviewAddText   接受: AdeReviewAdd   拒绝: AdeReviewDimmed
字符级标记只用于相似的行对；超过一半都变了的行只用整行底色。

statuscolumn 最左一格是状态条（▎，已决定块的首行为 ✓/✗），颜色为
AdeReviewStatePending/Current/Accepted/Rejected，三栏同一行同色；后面是真实行号
（原文/提案保留各自文件的行号，结果列按当前结果计数），filler 行没有行号。
行号栏不画折叠列：foldcolumn 恒为 0，foldcolumn 配置项已废弃并被忽略。
光标所在块在结果列行尾显示 ga/gr 提示（AdeReviewHint，hints = false 关闭）。
winbar 每栏一个彩色徽章（A 原文 / → 结果 / B 提案），只有结果列显示计数。
光标行用 AdeReviewCursorLine（复制 CursorLine 底色、去掉下划线）。
filler 用 AdeReviewFiller，fg 是固定的低对比灰。
所有组静态定义，运行期不算颜色：AdeReviewAdd/Delete/Pending 的底色复制自主题的
DiffAdd/DiffDelete/DiffChange，AdeReviewAddText/DeleteText 复制自 DiffText（只复制 bg，
ColorScheme 时重新复制）。card 使用 AdeDiffAdd/AdeDiffDelete。
可通过 ui.highlights 配置（ColorScheme 后重新应用），或 setup 后 nvim_set_hl 即时调整：
>
  ui = { highlights = {
    AdeReviewAdd = { bg = "#243c2c" },
    AdeReviewDelete = { bg = "#44292e" },
    AdeReviewPending = { bg = "#26384a" },
    AdeReviewAddText = { bg = "#2f5a3a" },
    AdeReviewDeleteText = { bg = "#6a3038" },
    AdeReviewFiller = { fg = "#4b5260" },
  } }
<
窗格选项只写窗口局部值，打开后立即恢复“新窗口继承值”，审查期间新开的浮窗不会继承
statuscolumn、折叠或审查 winhighlight。若外部仍换掉窗格 buffer，重新进入时放回并
恢复选项。审查窗口设置 winfixbuf，:edit/:enew/:bnext 会被拒绝（E1513），关闭窗口仍允许。
每栏按文件语言显式启动 Tree-sitter；缺少 parser 时静默回退到 legacy syntax。
光标停在变更块上时 ga 接受、gr 拒绝；Visual 选区可一次处理覆盖的所有块。
默认（advance = true）处理完一个块后自动跳到下一个待处理的块。
]c/[c（或 ]h/[h）按审查顺序循环跳到下/上一个块，已决定的块仍可访问；
三栏显示行一一对应，任意一栏都可以选择、决定和跳转，光标留在当前栏。u 清除当前块的决定。g2/g3 全部，g1 对本 buffer 永久接受，
q/<Esc> 拒绝剩余并关闭。
write 直接写回，但仍可一次撤销。filetype 可单独覆盖：

    inline = {
      review = {
        mode = "diff",
        by_filetype = { markdown = "write", text = "write", ["*"] = "diff" },
      },
    }

解析顺序：精确 filetype、复合 filetype 第一段、"*"、默认值。
浮窗外观与位置可配置，颜色仍来自 highlight group：

    inline = {
      window = {
        border = "rounded",   -- none/single/double/rounded/solid/shadow
        title_pos = "left",   -- left | center | right
        style = "minimal",    -- minimal | default
        highlights = {
          normal = "AdeInlinePrompt",
          border = "AdeInlineBorder",
          title = "AdeInlineTitle",
        },
        prompt = {
          placement = "cursor", -- cursor | window
          width = 72,
          height = 3,
          offset = { row = 0, col = 0 },
          follow_cursor = true,
        },
        review = {
          placement = "center", -- center | cursor
          width = 140,
          height = 25,
          target = "buffer",    -- buffer | float
          layout = "3-column",  -- 3-column | 2-column
          context = 3,
          syntax = true,
          advance = true,
          max_rows = 4000,
          min_split_width = 90,
          fold = false,
          sync_scroll = true,
          relative_number = false,
          hints = true,
          foldcolumn = 0, -- 已废弃并被忽略：行号栏始终不画折叠列
        },
      },
    }

placement = "cursor" 优先放在光标下方，空间不足时翻到上方，并始终夹在屏幕内；
follow_cursor = false 让输入框停在打开时的位置。审查内容随窗口尺寸自动重排。
:Ade inline [diff|write]、:Ade inline-stop、:Ade inline-reset 是对应命令。
内联通过当前 session 的正常 prompt 回合执行，回复保留在聊天记录，不创建新会话。
当前回合或队列未完成时拒绝 inline 提交；inline 期间普通聊天仍可排队。
命令支持行范围；显式 diff/write 优先于 always-accept 和 filetype 配置。
审查按结果到达时的 filetype 解析，<C-d> 切换本次模式；同一时间只运行一个请求。

23b. 团队、看板与流程（teams，实验性）                             *ade-teams*

服务声明 teams 能力（服务 0.7.1+，api_version 6）。你正在聊天的会话就是
leader，它可以按需启动 worker（各自是一个独立的 agent 会话，可以在自己的
git worktree 里工作），worker 之间通过服务总线（bus）传消息；团队和看板
保存在服务里，Neovim 退出后继续运行。

服务里没有流程状态机：流程只是一段 leader 遵循的约定，服务只负责校验、
保存、转发和提取。看板同理：服务保存结构，不解释列名或字段的含义。

概念 ~
                                                          *ade-teams-concepts*
leader      你正在聊天的会话。一个工作目录只有一个 leader；换 leader 要先
            结束团队。leader 的 agent 和模型就是那个会话本身的。
worker      服务按模板启动的参与者，名字形如 w1、reviewer（匹配
            [a-z0-9][a-z0-9_-]*，最多 32 字符，不能叫 leader 或 human）。
            它用总线工具（bus_send、bus_ask_human、bus_status、
            card_update）和 leader 通信。
模板        描述“用哪个 agent、怎么启动”：agent 必填；model 是默认模型，
            spawn 不带 model 时用它；models 是允许 leader 指定的模型列表
            （不写 = 不限，指定时必须在此列表里）；role 可选（写死的角色
            说明）；worktree = true 时在独立 worktree 里运行。
命名流程    一份“流程说明 + 团队组成”，可以内置、写在配置里，或由 leader
            按你的要求保存到服务数据库（项目级或用户级）。见
            |ade-teams-workflows|。
看板        每个团队一块：列、卡片、负责人、阶段。leader 管结构（列、
            建卡/删卡、挪列、指派负责人），worker 只写自己负责卡片的正文
            和键值。卡片是给你看的，不是 agent 之间的信息通道：agent 没
            有读取卡片内容的工具。
阶段        默认流程把工作分成阶段；一个阶段的卡片都完成后，leader 汇总一
            次请你确认提交，不按卡片逐个问。确认后 worker（或 leader）
            归档卡片。

看板限制：最多 16 列、200 张未归档卡片、500 张已归档卡片（超出时丢弃最旧
的），整块看板最多 256 KiB；卡片正文最多 8 KiB，fields 最多 12 个键、每个
值最多 120 字符。超出时服务拒绝这次写入，看板保持不变。

默认流程 ~
                                                      *ade-teams-default-flow*
不指定流程时，leader 按内置的 default 流程工作：

1. 你提出需求；leader 做设计，把工作分成若干阶段，每个阶段拆成任务并在看
   板上建卡（卡片的 stage 写阶段名）。默认列：待开发 / 进行中 / 审查中 /
   等你决定；等你决定只放需要你拍板的问题，不放“等提交”的卡片。
2. leader 按需 team_spawn worker，每张卡片指定负责人，发 task 消息。
   worker 在自己的 worktree 里开发，进度写在卡片上。
3. worker 做完后 report；leader 审查改动、跑测试。不通过就发 review 打
   回，卡片回到进行中。
4. 单张卡片通过后不问人：leader 把这名 worker 的分支合并到本阶段的集成分
   支（例如 ade/<team>/<stage>，在单独的 worktree 里合并，不改动主工作区
   的 HEAD），再给 worker 发完成确认；worker 归档卡片。worker 已经退出时
   由 leader 归档。
5. 阶段完成后一次性问你：本阶段的卡片都归档后，leader 汇总这一阶段做了什
   么（每张卡片的标题和结论、集成分支上的测试结果、需要你注意的地方），
   请你确认提交。
6. 你确认后，leader 把集成分支合并进主分支、清理本阶段的 worktree 和
   worker 分支；你不同意时，按你的意见在下一轮修改，或放弃整个集成分支。
7. 你也可以事先授权“阶段完成后直接提交”，那第 5 步只汇报、不等确认。

默认流程的正文可以整体替换：在配置里写 teams.workflows.default（见
|ade-teams-config|）。

对话定制流程 ~
                                                       *ade-teams-custom-flow*
准备组队时，leader 先把计划复述给你确认：团队组成、每个人用什么 agent 和
模型、看板列、每一步谁做什么；你同意后再组队，并把流程写进看板的
workflow 字段。

例如你说：

    做 xxx 工作，你来做主要设计和任务分解，生成两个 opencode 的 worker
    写代码，opencode 的 worker 使用的模型是 xxx，然后用一个 pi 的
    reviewer 来审核代码，reviewer 使用 gpt6.1sol 模型。

leader 会这样组队（每次启动 worker 默认都要你在选择组件里确认；一键批准
见 |ade-teams-panel|）：

    team_spawn {template="opencode", name="w1", model="xxx",
                role="写代码…"}
    team_spawn {template="opencode", name="w2", model="xxx",
                role="写代码…"}
    team_spawn {template="pi", name="reviewer", model="gpt6.1sol",
                role="审查…"}

流程中途也可以改：你说“以后测试也交给 reviewer 跑”，leader 更新看板上的
流程并照做。

命名流程 ~
                                                         *ade-teams-workflows*
一个命名流程：

    {
      name    = "review_by_pi",      -- [a-z0-9][a-z0-9_-]{0,31}
      summary = "opencode 写代码，pi 审查",  -- 一行，最多 120 字符
      text    = "……",                -- 全文，最多 4 KiB；省略 = 默认正文
      leader  = { agent?, model?, role? },  -- 只有明确要求时才有
      team    = { { name, template, model?, role?, task? }, ... },
                                        -- 0..8 个 worker
      columns = { "待开发", "进行中", "审查中", "等你决定" },
                                        -- 1..16 列
    }

team 只列 worker，永远不含 leader；成员名字不能重复，也不能是 leader 或
human；template 必须是已配置的模板，成员的 model 必须在模板的 models 列表
里（有列表时）；成员 role 最多 16 KiB，task 最多 64 KiB；列标题每项 1..40
字符且不能重复。summary 和 text 至少要写一个；只写 text 时 summary 取正文
第一行。leader 里写了 agent 时，它必须是已配置的 agent；leader.role 最多
4 KiB。

流程成员数不能超过 teams.max_workers（默认 3，范围 1..8）：配置校验会拒绝
超过的流程；运行中剩余成员会超过 max_workers 个活 worker 时，team.start
整体拒绝，一个都不启动。

来源与解析顺序（同名取靠前的）：config > project > user > builtin。

    config    配置里的 teams.workflows，只读，leader 不能改
    project   leader 保存到服务数据库、只在这个仓库可用
    user      保存到服务数据库、所有项目可用
    builtin   内置的 default（空团队 + 四个默认列 + 默认正文）

项目级流程按团队 cwd 所在 git 仓库的公共目录（git rev-parse
--git-common-dir 的规范路径）区分，所以同一个仓库的各个 worktree 共用；不在
git 仓库里时按 cwd。

用法：

- 保存：你说“把这个流程存成 review_by_pi”，leader 调 workflow_save。同名
  的已存流程会被拒绝（返回错误），leader 问你是否覆盖；你同意后带
  replace = true 再存。与配置里的流程同名也会被拒绝——配置的同名流程会
  遮住它。每个范围（项目或用户）最多保存 100 个流程，超出返回 -32061
  “too many workflows”。保存不弹额外确认：保存的只是文字和组队计划，
  真正启动 worker 时仍走 spawn 确认。
- 使用：你说“用 review_by_pi 流程做 xxx”，leader 先读全文、复述计划，你
  确认后按 team 组队、按 columns 建看板，把 text 写进看板并在看板上记下
  流程名。
- 查看和删除：:Ade workflows 列出所有命名流程（名字、范围、一行说明、成
  员），<CR> 看全文，d 删除对话保存的流程（config/builtin 只提示不能
  删）。也可以在对话里让 leader 删除。
- 省 token：leader 平时只在 bus.status 里看到名字、一行说明和范围；全文
  只在用到时用 workflow_get 读取。

流程里的 leader ~
                                                   *ade-teams-workflow-leader*
leader 默认就是你正在对话的那个会话，流程不改变它。只有你明确要求时，流程
里才写 leader：

- role：追加在 leader 的团队说明后面（只出现一次）。
- model：当前 leader 的 agent 提供这个模型时，前端会切换过去并告诉你；
  不提供时只提示，不切换。
- agent：和当前 leader 的 agent 不同时不会自动换 leader。:Ade team start
  会问你是“另开该 agent 的会话作为 leader（有团队时先结束）”还是“忽略，
  用当前 leader”。

leader 保存流程时，只有你在对话里明确提到 leader 的 agent、模型或角色，才
写 leader 字段。

配置 ~
                                                            *ade-teams-config*
    teams = {
      enabled = false,         -- true: 建团队后按 default 流程自动组队
      default = "dev",         -- 默认流程名（或 "default"）
      workflows = {            -- 命名流程；同名时覆盖内置的 default
        dev = {
          summary = "两个 opencode 写代码，leader 审查",
          text = "……",          -- 省略时用默认流程正文
          columns = { "待开发", "进行中", "审查中", "等你决定" },
          team = {
            { name = "w1", template = "opencode", model = "xxx",
              task = "T1" },
            { name = "w2", template = "opencode", model = "xxx" },
          },
        },
        review_by_pi = {
          summary = "opencode 写代码，pi 审查",
          leader = {
            agent = "claude",
            role = "只做设计和审查，不亲自改代码",
          },
          team = {
            { name = "w1", template = "opencode" },
            { name = "reviewer", template = "pi" },
          },
        },
      },
      spawn_from_chat = true,  -- 允许 leader 从聊天里组队
      max_workers = 3,         -- 每个团队最多 3 个 worker（1..8）
      spawn_confirm = { auto = {} }, -- 列出的模板无需人工确认
      limits = { max_turns_per_task = 30, max_turns_total = 200 },
      templates = {
        opencode = {
          agent = "opencode",  -- 必须是已配置的 agent
          model = "xxx",       -- 默认模型；spawn 不带 model 时用它
          models = { "xxx", "yyy" }, -- 允许指定的模型；省略 = 不限
          worktree = true,     -- 独立 git worktree（默认 false）
        },
        pi = {
          agent = "pi",
          role = "按 leader 分配的卡片审查代码。", -- 可选
        },
      },
      dashboard = { wide = 160 },  -- 面板宽度阈值（40..10000）
    }

注意：旧的 teams.definitions 和 teams.workflow 已删除，配置里出现时 setup
直接报错（错误里给出新写法），不做迁移。流程必须有 summary 或 text 之一：
只写 text 时 summary 取正文第一行；只列成员、两者都不写会报错。每个流程的
team 人数不能超过 max_workers，否则 setup 报错（写明流程名和两个数字）。

迁移示例：

    旧：
        teams = {
          definitions = {
            dev = { workers = {
              { name = "w1", template = "opencode", task = "T1" },
            } },
          },
        }

    新：
        teams = {
          workflows = {
            dev = {
              summary = "一个 opencode worker",
              team = {
                { name = "w1", template = "opencode", task = "T1" },
              },
            },
          },
        }

替换默认流程正文：teams.workflows = { default = { text = "……" } }。

启动团队 ~
                                                             *ade-teams-start*
三种方式：

对话          直接对 leader 说要做的事。leader 按上面的约定组队；每次
              spawn 都要你在选择组件里确认，可以逐个批准或一次全部批准。
命令          :Ade team start [流程]。已有命名流程时最快；不用逐个确认。
自动          teams.enabled = true 时，leader 建好团队、且团队还没有
              worker，前端调用一次 team.start {default 流程}；重连或
              第二个前端不会重复。

:Ade team start [流程] 的步骤：

1. 没给流程名时，用 team.workflows 的结果弹出选择器（名字、一行说明、
   范围）。
2. 流程要求别的 leader.agent 而当前会话不是时，问你是“另开该 agent 的
   会话（有团队时先结束）”还是“忽略，用当前 leader”。
3. 当前 cwd 已有带 worker 的团队时问你：“结束后重新开始”“只补流程里缺
   的成员”或“取消”。
4. 输入这次的任务（可留空）。取消输入就什么都不做：不关团队、不切换
   agent、不新建会话。
5. 确保 leader 会话：没有会话时打开聊天并新建，等待 leader 绑定。
6. 调 team.start：服务按流程逐个启动成员（已在团队里的名字跳过），再给
   leader 发一条 notice：基础说明、任务、流程名和正文、成员（名字、模
   板、agent、模型、角色）、看板列。leader 收到后建看板、分派任务。
7. 成功后自动打开团队面板（:Ade team）。

流程的 leader.model 存在时，前端在当前 agent 提供该模型时切过去并提示；不
提供只提示。团队被挂起（等待 leader 会话恢复）时 :Ade team start 会提示先
恢复；当前 cwd 没有 leader 会话或团队不属于本前端时会提示，不会去抢别的
会话的团队。

旧服务（api_version 5）上没有 team.start/看板/流程接口：前端提示“服务版本
过旧；空闲后会自动更新，或用 :Ade service stop 手动重启”，不会反复重试看
板。

命令 ~
                                                          *ade-teams-commands*
:Ade team                                                          *:Ade-team*
    打开统一团队面板；没有团队时显示空状态（可用流程列表：光标所在流程按
    S 启动，<CR> 看全文）。

:Ade team start [流程]                                       *:Ade-team-start*
    按流程启动团队，见上。

:Ade team close                                              *:Ade-team-close*
    结束当前 cwd 的团队（确认后 team.close）。当前 cwd 没有团队时提示，
    不会关闭别的目录的团队。

:Ade team answer [名字]                                 *:Ade-team-answer*
    显示待处理的选项（提问、spawn、权限、上限）；带名字时用输入框回答该
    成员没有选项的提问。

:Ade workflows                                                *:Ade-workflows*
    列出命名流程：名字、范围、一行说明、成员。<CR> 看全文，d 删除（只限
    project 和 user；config/builtin 提示不能删），q 关闭。

补全：:Ade team <Tab> 补全 start/close；:Ade team start <Tab> 补全流程名
（配置里的、已知的服务流程名和 default）。

面板 ~
                                                             *ade-teams-panel*
`:Ade team` 打开统一面板：成员和看板两栏，标题只在 tabline。

宽屏（列数 >= teams.dashboard.wide，默认 160）在独立 tabpage 里打开：左边
成员、右边看板；观察 leader 或 worker 时右侧再加一列观察窗口。q 关闭整个
tabpage，回到原来的位置。<Tab> / <S-Tab> 在窗口之间切换。

窄屏保持居中浮窗，从上到下只有成员和看板两段；看板一次显示一列，zh / zl
横向滚动。两种布局都用同一套成员、看板和高亮。

标题    tabline 一行：团队、cwd、状态、workers x/y、回合数、流程和阶段进
        度，以及 ? 待回答 N / ⚑ 待批准 N。窄屏时待处理计数排在最前，先省
        略 cwd。
成员    leader 在最上面（★、强调色），下面是 workers N/max。每个 worker
        显示符号和角色色（◆）、名字、label、agent/短模型名、状态（● 工作
        中 / ○ 空闲 / ? 等你回答 / ⏸ 暂停 / ✕ 退出）和已持续时间、任务
        与未读消息（✉ N）。宽度不够时先缩短模型，再缩短 agent；放不下的
        模型会换到第二行。第二行还显示 ↳ 最近动态，第三行显示 worktree 分
        支。成员栏宽度由 teams.dashboard.members_width 决定（默认 32，
        16..120），winfixwidth + nowrap；手动拖动后本次打开期间保持，下次
        打开恢复配置值。
看板    列之间是粗竖线（┃），列标题带数量和底色；卡片是圆角框，负责人用
        角色色画边框，光标所在卡片高亮。列宽只由窗口宽度决定，不随标题长
        度跳动；列太多时横向滚动（zh / zl），标题行固定。已归档的卡片按阶
        段折叠显示（例如“S1 · 已提交 · 6 张”）。leader 还没写过看板时显示
        “leader 还没有创建看板”和“按 L 去和 leader 聊”。
详情    卡片上按 <CR> 打开浮窗：正文、fields、更新者、时间；q 或 <Esc>
        关闭。成员上按 <CR> 打开或切换观察窗口。
消息    worker 发给人的普通消息用 vim.notify 提示，并在该成员行显示 ✉ N；
        在观察窗口里能看到正文。

多个团队时 tabline 显示 [1/2]，]t / [t 切换。

按键作用于光标下的对象：

    成员上
      <CR> / w      打开或切换这个人的观察窗口
      m             给这个人发消息
      a             回答这个人的待回答提问
      p / r / c     暂停 / 恢复 / 取消当前回合
      D             删除已退出 worker 的 worktree
                    （确认；可 force；未合并分支保留）

    卡片上
      <CR>          打开卡片详情浮窗
      m             就这张卡片给 leader 发消息
      H             查看历史版本（逐版对比）
      w             打开负责人的观察窗口
      p / r / c     对负责人生效

    全局
      !             打开待处理的选择（提问、spawn、权限、回合上限）
      L / s / R / x / g? / q
                    跳到 leader 聊天 / 按模板启动 worker / 重置回合
                    上限 / 结束团队 / 帮助 / 关闭
      <Tab> / <S-Tab>       切换窗口（宽屏）
      zh / zl               横向滚动看板

看板卡片上按 m 发消息时走总线排队（kind = notice，task = 卡片 id），不会
打断 leader 正在跑的回合；服务在正文前加一行卡片摘要（id、标题、列、负责
人、fields），leader 由此知道你说的是哪张卡片。

spawn 组：leader 在同一个回合里发出的多个 spawn 申请带同一个 group；在
选择组件里可以逐个批准，也可以选“全部批准”。

需要选择时 ~
                                                     *ade-teams-choice*
需要你从选项里选时（带选项的提问、spawn 申请、worker 权限、回合上限、
agent 自己的权限请求和表单），聊天窗口底部会浮出一张选择卡片；输入框、
草稿和附件保持可见、不受影响。卡片高度随内容自动调整（切题、展开、输入
“其他”时都会重算，最多约占聊天窗口的 60%，超出在卡片内滚动）；转录区底部
留出等高空白，最新输出不会被遮住。

- Tab / Shift-Tab（也接受左右、h/l）切换问题，↑↓/jk 选择，1-9 直接选，
  Space 多选，Enter 确认，Esc 稍后（团队权限也是稍后；只有 agent 自己的
  权限请求和表单是取消）。
- 没有选项的提问不占组件：只提示，用 :Ade team answer 或在成员上按 a
  回答。
- 光标在聊天或输入窗口时卡片直接获得焦点；否则只提示，回到面板后按
  <M-a>（keymaps.chat.focus_choice / keymaps.input.focus_choice）进入。
  回答或 Esc 后光标回到输入窗口。
- 面板隐藏时卡片随之关闭，只提示；:Ade open 或 :Ade team answer 后显示。
- 卡片缓冲区的 filetype 是 ade_choice，并设置 b:ade_choice。

观察窗口 ~
                                                             *ade-teams-watch*
在成员上按 <CR> 或 w 打开右侧的观察窗口，用来完整查看这个人的工作过程。

worker：只读，从它会话的第一条消息开始完整重放（内容和聊天窗口一致：总线
消息、回复正文、工具调用可展开、编辑显示 diff、plan、思考默认折叠），再接
实时更新；按回合分组，za 折叠回合，[[ / ]] 跳回合；停在底部时自动跟随，
往上翻暂停，G 回到底部。窗口里没有输入区，也不能回答问题：权限请求和提问
可以在观察窗口里直接回答（和聊天窗口一样）。对 worker 说话仍然只能在成员
列表里按 m。

worker 观察窗口下方有输入区：<C-s> 把消息作为 notice 排队发给这个 worker，
并抄送 leader（leader 收到一条 notice）；<M-CR>（可用
teams.dashboard.keys.interrupt 改，默认 <M-CR>）先在输入区上方提示“再按一次
确认打断”，再按一次才 cancel 当前
回合并优先送达。草稿按 worker 分开保存；切到 leader 时仍复用 leader 聊天，
不显示这个输入区。输入区 filetype 是 ade_team_input：blink/cmp 的 per_filetype
只写了 ade_input 时需要再加上它；粘贴图片和附件在这个输入区不可用。worker
对被打断后新消息的回答仍会作为 report 抄给 leader。

leader：观察窗口显示 leader 的聊天会话本身（你和它的对话 + 总线回合），
带输入区：在那里发出去的就是你给 leader 的 prompt（你的 prompt 优先于排队
的总线消息）；权限和提问也能直接回答。如果 leader 的聊天窗口已经打开，观
察窗口复用同一个聊天会话，不会出现两份输入状态。

会话日志超过 32 MiB 时不能从头重放，窗口顶部提示“会话过长，只显示观察开
始之后的内容”，并用 team.read 补上最近的消息和最后 3 个回合的正文；不做
分段重放。

工作流、看板与 token ~
                                                      *ade-teams-board-tokens*
leader 的说明分两层：

- 基础说明：每个可当 leader 的会话建立时，MCP initialize 的 instructions
  字段就会带上（最多 2 KiB，约 300 token）：能组队、只在被要求或提议获准
  后组队、看板与命名流程的约定。claude/opencode 会把它放进上下文（可被提
  示缓存），pi 不读；所以每个 leader 会话都有这份固定开销，不组队也一样。
- 流程全文：只在组队开始时通过一条 notice 发一次，加上成员和任务（基础说
  明会再带一次）。不组队就不会收到流程全文。

各 agent 对 MCP instructions 的支持（2026-11-17）：

    agent      支持  版本与方式
    claude     是    claude-agent-acp 0.107.0：系统提示里的 MCP Server
                     Instructions 段；会话中途新增的 server 以增量说明
                     补上
    opencode   是    2.3.0：作为上下文里的 MCP 指导块
    pi         否    @geohar/pi-acp 0.4.0 → pi-mcp-adapter 7.0.0：适配器
                     缓存 instructions 但不放进提示，模型要自己调
                     mcp({instructions="ade-team"}) 才看得到

pi 的工具还走它自己的 mcp 代理：角色卡会写明用
mcp({tool="bus_send", args={…}}) 调用团队工具。

看板变化不叫醒任何 agent：不进入 leader 或 worker 的信箱，也不触发回合；
只有前端收到 team.board_changed 后重新拉取。worker 更新自己的卡片不花
leader 的 token；leader 收到的汇报里应当包含做决定需要的细节，而不是“见
卡片”。

持久化 ~
                                                           *ade-teams-storage*
团队、参与者、排队消息、最近 200 条消息正文、看板、卡片历史和命名流程都写
入服务的事件日志数据库（权限 0600）。看板和卡片历史随团队删除；命名流程不
随团队删除。模板的 key/env/launch 不落盘，恢复时要由前端重新提供配置。

服务重启后未关闭的团队变为挂起（suspended）：面板照常显示，标注挂起时间和
“等待 leader 会话恢复”。恢复 leader 的会话后团队自动继续，worker 按存储
的 session 和 worktree 恢复，恢复 notice 作为 bus 回合出现在 leader 聊天
里。挂起期间可以 m 发消息（排队）、回答 question/message/limit、R 重置回
合上限、D 删除已退出 worker 的 worktree、x 关闭团队；w/s/p/r/c 提示团队
已挂起。挂起超过 7 天的团队会在服务启动或每小时检查时删除（worktree 与分支
保留）。如果恢复出的会话不是存储的 leader，团队保持挂起，并提示在面板按 x
关闭；leader 注入不会被挂起团队阻塞。

--event-log off 时不声明 teams 特性，team.* 返回 -32601，团队、看板和命名
流程都不会落盘或恢复；此时 workflow_save 返回 -32061（no database）。

服务版本与插件不同且服务里还有团队时（挂起的团队除外）不自动重启，只提示稍
后重启；需要时用 :Ade service stop 手动重启。

worktree = true 的模板由服务在 stdpath("data")/ade/worktrees/ 下创建独立
worktree 和 ade/<team>-<stamp>/<name> 分支。worktree 只含已提交内容：团队
目录有未提交改动时提示 dirty_tree，worker 从最后一次提交开始。worker 退出
或团队关闭后 worktree 与分支都保留；面板 D 删除（可 force），未合并的分支
会保留。

直连模式、旧服务或 spawn_from_chat = false 时不注入 team MCP server，单
agent 行为不变。

24. 服务后端（nvim_ade_server）                          *ade-service*

Agent 可以交给 Rust 后台服务 nvim_ade_server 持有，这样 Neovim 退出后 agent 继续运行，
重新打开时按同一个实例 key 附着回去。默认 backend = "auto"：服务可用就用服务，没装
服务则安静回退 Lua 直连（只提示一次），不装服务也能照常使用：

    backend = "direct"    Neovim 自己启动并持有 agent（与旧行为一致）
    backend = "service"   通过服务通道收发 ACP；服务不可用时明确报错，不回退
    backend = "auto"      服务可用就用服务，不可用只提示一次再回退直连（默认）

服务提供 policy 能力（0.5.0+）时，permissions.auto_allow 以规则集下发给服务，由服务
替 agent 回答权限请求：Neovim 退出、没有前端附着时自动允许依然生效（无人值守），需要
人工判断的问题照常转发。inline 回合会在 session/prompt 之前下发只作用于该回合的规则：
只能编辑私有副本（inline.allow_writes 可放开全部编辑，inline.allow_commands 放开 execute，
inline.allow_kinds 追加其它 kind），其余拒绝，回合结束自动删除。服务做出的决定会在聊天
里显示 auto-allowed / auto-rejected / auto-cancelled，重放历史也保留。旧服务与直连模式
仍由 Lua 策略执行，行为不变。

安装（lazy.nvim 的 build 钩子）：

    {
      "btstream/ade.nvim",
      build = function() require("ade.service.install").run() end,
    }

其他插件管理器在安装或更新后执行一次 `:Ade service install`。安装流程：已装所需版本
则跳过；否则先下载对应平台的预编译包并用 SHA256SUMS 校验（不一致直接拒绝），下载不可用时
用 cargo 本地编译；两者都失败只给出提示，插件继续以直连模式工作。服务使用
service/rust-toolchain.toml 锁定日期的 nightly 工具链，**建议安装 rustup**，它会自动获取
指定的 nightly；编译仍失败时，提示会写明需要 rustup，或者用 service.path 指向自己编译
的二进制。设置 service.path 后只运行 `<path> version` 做版本检查，不下载也不编译。

    service = {
      path = nil,                     -- 自备二进制，设置后跳过下载与编译
      release_base = "https://github.com/btstream/ade.nvim/releases/download", -- 必须 https（回环 http 例外）
      install_timeout = 10 * 60 * 1000,
      start_timeout = 5000,
      keep_alive = true,              -- 退出 Neovim 时让 agent 继续运行
      idle_timeout = 1800,            -- 空闲多少秒后服务自行退出（60-86400）
      event_log = true,               -- 记录事件日志，供下次打开时重放
      event_log_max_mb = 256,         -- 每个实例的日志上限（16-4096 MiB）
      restore = true,                 -- 打开时恢复上次在这个目录里的会话
      restore_on_restart = true,      -- 新启动 agent 实例时也尝试恢复（默认）
      reconnect_attempts = 8,         -- 意外断线后的自动重连次数（0 关闭）
    },
    backend = "auto",                 -- "direct" | "service" | "auto"（默认 auto）

keep_alive = false 让每次退出（关闭 Neovim、切换 agent）都停掉 agent，等价于直连模式。

事件日志只在 agent 实例存活期间保留，保存在服务目录，实例停止或服务重启即删除；
event_log = false 关闭记录后，重新打开看不到离开期间的内容。

退出 Neovim 不会关闭会话：会 detach 时（agent 继续运行）不发 session/close，只有显式关闭、
删除或切换会话才发。keep_alive = false 与直连后端照常关闭。
restore = true 时，附着到已在运行的实例后会自动重新打开该工作目录下最近有活动的会话，
而不是新建空会话；没有匹配、agent 不支持 session/load 或加载失败时回退新建并提示一次。
restore_on_restart = true 时，ADE 按 agent 和工作目录保存上次选中的会话 ID；
新启动 agent 实例后也会尝试恢复。仅支持 session/resume 时不回放历史。会话不存在则
新建，临时错误保留记录，重新打开可重试。不保存历史、队列或凭据。

服务模式下意外断线会自动重连：0.5s、1s、2s、4s、8s，之后每 15s，最多
reconnect_attempts 次（默认 8）。状态栏显示 reconnecting (n/8)，成功后提示一次；
全部失败后停止并提示，仍可 :Ade reconnect。

版本不一致时：api_version 相同则服务空闲就自动重启到新版本；有任务在跑就先用着并提示一次。
api_version 不同则用服务报告的版本再握手一次，再按同样规则处理。

重启服务会连带停掉服务里还活着的 agent（它们是服务的子进程），通知里写明
restarting nvim_ade_server (X -> Y); N idle agent(s) will restart with it。空闲判据保证
没有进行中的回合、没有待处理的权限/elicitation 请求、也没有别的 Neovim 附着；重启后
会话依赖 agent 自己的 session/load 恢复。

release_base 必须是 https://：压缩包与 SHA256SUMS 同源，明文 http 下中间人可同时替换两者，
校验失效；下载时 curl 也限制 --proto =https --proto-redir =https，不允许跟随重定向降级。
唯一例外是回环地址（localhost、127.0.0.1、[::1]）可用 http://，用于本地测试服务器。
URL 中出现反斜杠、空白或控制字符，或 authority 里带 @（userinfo）一律拒绝：这些写法在
不同 URL 解析器里含义不一致（浏览器会把反斜杠当路径分隔符），不适合指定发布源。

命令：

    :Ade service install    安装服务（异步，进度用通知显示）
    :Ade service status     已安装版本、二进制、是否在运行、api_version 是否匹配
    :Ade service start      在后台启动服务；已在运行则复用
    :Ade service stop       让服务退出
    :Ade service agents     列出服务持有的实例（id、agent、cwd、pid、运行时长、
                            附着数、进行中的回合、待处理请求）
    :Ade service kill <id>  停掉一个实例

服务模式下 :Ade disconnect 会真正停止 agent；关闭 Neovim 或切换 agent 时按
service.keep_alive 决定 detach（保留）还是 stop。stop 与 detach 都不阻塞界面：
服务在处理请求时就把实例从身份表摘掉，所以紧接着用同一个 key attach 一定得到新实例。

多个 Neovim 附着同一实例时，每个连接都会收到该实例的全部 session/update；不属于
自己的会话的更新会被 reducer 直接丢弃（不缓冲），正在创建会话的那一小段时间最多
缓冲 256 条 / 1 MiB；客户端待派发队列上限 64 MiB，超出时不丢消息，而是按连接丢失
处理（断开并让各实例通道上报退出），重新连接即可。

`:checkhealth ade` 中的 “ade.nvim service” 一节与 status 相同，只报告不修改。
服务目录、socket 与令牌路径：优先 $NVIM_ADE_SERVER_DIR，其次 $XDG_RUNTIME_DIR/ade、
$XDG_STATE_HOME/ade，最后 ~/.local/state/ade。
